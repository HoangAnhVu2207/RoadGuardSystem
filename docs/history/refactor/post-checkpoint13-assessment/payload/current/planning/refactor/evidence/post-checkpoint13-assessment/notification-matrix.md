## Recommendation

RETAIN (PROPOSED): preserve recipient query/projection/pagination, actor-scoped command receipts, consumer/message receipts, owner-checked leasing and each producer's atomic transaction. Shared SaveChanges/JSON/BeginTransaction syntax is not a common policy. Only the pure SQL unique-error predicate identified in the idempotency assessment is a possible small later extraction, subject to exact catch-filter equivalence.

Later proposal gates: isolate source ownership; keep unique receipt keys and transaction participation; characterize existing wire/pagination and ownership/attempt semantics; verify cancellation, concurrent workers, expired lease, capped attempts, commit acknowledgement and direct worker path on owned SQL; provider/scheduler integration separately. Dispatcher, retention, new endpoint or migration are F/G and not implemented here.
