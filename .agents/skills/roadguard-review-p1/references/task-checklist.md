# P1 review lenses

This is a retrieval aid, not a replacement plan or an assertion that every listed task is implemented. Read the current assigned row and traced specifications. Test omissions apply only to relevant behavior in that slice.

| Task family | Decisions and failure paths to inspect |
|---|---|
| P1-00/01 | Actual solution/project reference graph; BusinessObjects has no dependency on API/Services/Repositories/DTOs. Startup, versioned API/OpenAPI, sanitized ProblemDetails, stable error code/correlation and health behavior have meaningful negative and positive tests. Preserve existing names/target. |
| P1-02 and later tooling rows | ADR/spec/plan consistency, current paths and discovery, mirrored AGENTS, preserved Git/ownership rules. Verify documents/scripts and Codex Implementer versus independent Codex Reviewer authority; do not demand HTTP tests for prose or revive retired review task IDs. |
| P1-10/11/12 | Login/refresh/logout, hashed refresh credentials, replay/revocation and forced password-change enforcement. Current `User.role_code` validates role snapshots and Supervisor bypass; effective `ProjectMember.role_code` grants project permissions. Role/membership changes affect the next request; reset/profile updates cannot self-escalate. Inspect per-task test matrix, including wrong project and changed role. |
| P1-20/21 | Exactly one active primary PM across atomic reassignment; warranty/handover dates; no automatic liability decision. New road geometry creates a RoadSectionVersion; referenced versions remain immutable. Project closure checks all documented open-work gates. |
| P1-22/23 | Plan/request/survey assignment transitions follow their actor and state matrix, correct road version, scope/dates and reasons. Reject-after-accept, duplicate active assignment, stale/cancel-after-confirmation are checked where applicable. |
| P1-30 | Resumable upload metadata/chunks/completion validate size, checksum, required files and assignment/project. Duplicate key with changed payload fails. FE retry queues do not bypass current access checks. Client completion cannot mark SERVER_CONFIRMED; backend worker requires server integrity/quality gates. |
| P1-31/32 | Adapter validates result schema, project/input/model provenance, stale attempt and timeout/retry class. Deterministic mock remains behind the boundary. Keep creates exactly one OPEN defect and required inspection task; reject/edit preserves raw AI output. No direct VERIFIED transition. |
| P1-40/41/42 | Assignment/session/measurement uses correct project/road version and client IDs. Submitted measurements are immutable; supplements append. Only PM verifies/rejects after required completed task and submitted measurements. Baseline independently checks files, jobs, detections, tasks and defects; retry remains idempotent. |
| P1-50/51/52 | Eligible VERIFIED defects and inspection prerequisites; no duplicate active repair; money overflow/rounding and server-calculated total. Submit locks version; approval/return/reject preserves history. Resubmit creates N+1. Assignment checks current approved version at decision time, including stale races. |
| P1-53 | Per-item progress, confirmed before/after evidence, inspection/rework and Supervisor final confirmation. Passed items do not regress; batch closes only when all required items pass. No update-in-place of repair evidence. Unplanned defect handling does not silently add a repair item. |
| P1-60/61 | Scoped query and drill-down IDs, no duplicate version counting; separate pending/approved/actual cost meanings. Export idempotency, limits, status/download reauthorization; manifest retains filters, versions and checksums. |
| P1-62 | Retention request/review actor rules, hold and scope gates, stale decisions, immutable approved scope and accurate dry run. Executor rechecks legal hold under P2 ownership. Dry-run success is not permission to delete. |
| P1-63 | Research import/pair/unit/type/exclusion rules and deterministic bias/MAE/RMSE/count; missing pairs/all-excluded input handled explicitly. Synthetic data labeled. Never create/transition operational Defect or Warranty automatically. |
| P1-64/65 | Admin role changes audit before/after and atomically revoke sessions/refresh tokens; preserve drafts/history and hand over open work. Versioned catalogs/rules/labels; reminders do not create surveys. Model/job/device scope, retry class, activation validity and approved-label export provenance. |

For every applicable lens inspect success plus forbidden actor/project, invalid state, stale version, duplicate retry and failed cross-aggregate persistence. Treat absent historical RED evidence separately from observed behavior. Avoid prescribing all cases to tasks that cannot exercise them.
