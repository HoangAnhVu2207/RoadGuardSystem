# Current persistence boundaries and caveats

This is current-checkout evidence, not an approved target architecture. For exact columns, FKs, unique indexes, checks and triggers use the [dictionary](current-data-dictionary.md) and [machine inventory](current-schema.inventory.json). A transaction or authorization decision cannot be inferred from an ERD.

| Flow | Current source and observed mechanism | SQL versus application guarantee / next check |
| --- | --- | --- |
| Actor/project | `ProjectAccessAuthorizationHandler` calls `ProjectScopeGuard` before `ProjectWorkPackagesController.Get`; `ProjectWorkPackageReadModel.ReadAsync` projects project, current road versions and warranties through three project-filtered no-tracking SQL queries. `ProjectWorkPackageService.GetAsync` maps those facts to the response and adds the authorized access role. | FK proves referenced rows, not current membership/effective-date authorization. RF-07's isolated HTTP/SQL characterization covers current/wrong actor, expired/cross-project scope, nullable and ordered child rows, and before/after business-row state. It does not establish deployed data or every table's write absence. |
| Idempotency | `IdempotencyOperationService.ExecuteAsync` uses `Database.CreateExecutionStrategy`, an explicit `BeginTransactionAsync`, and `IdempotencyRecords`; survey V2 and upload persistence call it. | Unique indexes and transaction scope appear in catalog/code; replay semantics, actor/project key scope and retry outcome require per-operation tests. Old survey path is separate and must not be treated as equivalent from table shape. |
| Concurrency | SQL `timestamp` catalog type represents EF `rowversion` on 17 columns. `SurveyV2PersistenceService` and `UploadPersistenceService` compare expected versions; `RowVersionConvention` applies EF concurrency metadata. | DB rowversion changes on writes; expected-version transport and stable error are application/HTTP behavior. RF-07 is read-only; RF-08/10 use isolated stale-write tests. |
| Transaction/outbox/audit | `SurveyPlanningPersistenceService` adds `AuditLog` in its command path; `IdempotencyOperationService` names its transaction; `OutboxMessages` and `ConsumerEffectReceipts` have SQL constraints/indexes. Migration SQL installs append-only/immutability triggers. | No universal transaction boundary is inferred. Inspect each command's SaveChanges/transaction and consumer call. `NotificationOutboxConsumer` exists, but RF-02 CG13 has no verified production dispatcher caller. |
| File/upload | `StoredFile.SizeBytes` is CLR `int` / SQL `int` with nonnegative check; `UploadSession.ExpectedSizeBytes` is CLR `long` / SQL `bigint`; `UploadService.ValidateCreate` rejects over `int.MaxValue`. `FileScopes` carries project association. | Current size cannot represent accepted 8 GiB pilot source (decision 38); RF-09/10-04 must plan additive conversion and consumer compatibility. `TR_Files_Immutable` exists. A file FK/scope does not prove object-storage bytes or retention deletion safety. |
| Spatial | `RoadSectionVersions.Geometry` is SQL `geometry`, with SQL checks for LineString and SRID 32648/32649. `GroundTruthMeasurements.Location` is `geography`, with SQL check SRID 4326 and nonempty. `Defects.Geometry` and `AIDetections.Geometry` are `geometry` without a cataloged SRID check. | `SpatialConstants` and repository behavior may expect UTM metres / GPS degrees, but only named checks above are DB enforcement. RF-06 spatial Testcontainers tests are a separate runtime baseline; source/catalog here do not prove every geometry uses a particular SRID. |
| Delete/retention | No EF query filters were found in the extracted design model. Catalog has 20 active migration-created triggers; FK delete actions are listed per table. `RoadGuardDbContext.ValidatePersistenceInvariants` rejects generic `StoredFile` deletion and several append-only mutations. | No generic soft-delete/retention policy follows from absence of query filters. Accepted 41A still needs deployed row/warranty/hold evidence and an approved removal plan; do not delete data based on this ERD. |

Business explanations above are limited to the cited symbols and [RF-02 gaps](../../../planning/refactor/02-contract-gaps.md). Confirmed requirements 32-44 live in [product decisions](../../product/confirmed-decisions.md); source behavior and SQL constraints are not proof those requirements are fulfilled.
