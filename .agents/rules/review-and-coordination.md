# Review and shared work

Self-review pass 1 checks the final diff against acceptance sources: contract, actor/project scope, transaction, retries, concurrency, data and external effects as applicable. Pass 2 checks file scope, shared writer, producer/consumer interface, docs/contract, rollback and behavioral conflict even when Git has no conflict. Fix in-scope defects, rerun affected checks and reread the final diff. A second agent is optional; never label self-review as peer review or fake integration as live integration.

ChatGPT provides technical direction, writes the spec and reviews the GitHub diff. Codex implements the whole assigned package, self-reviews/fixes and verifies it. Owner decides missing business, public compatibility and data policy. Steps within the assigned spec need no repeated approval. One agreed person edits each vertical slice through tests on `anh-review` or `huy-review`. Record allowed files/symbols, dependencies and shared reservations in the spec or PR discussion. Anh coordinates DbContext/migration/snapshot, canonical contract, shared DI and integrated Postman; no two simultaneous writers edit shared files. For cross-owner findings, record evidence, proposed fixer and integration order in that discussion; continue independent work without editing another writer's files or duplicating policy.

One assigned development spec and a short PR summary suffice; no seven-part RF report or separate coordination file is required. Record actual changes, base/HEAD/dirty preservation, both concise review passes, exact commands/results and counts, decisions/blockers and handoff conditions. Producer and consumer can progress against agreed versioned interfaces/fixtures; integration requires real BE producer/consumer evidence. External AI/Android checks use fixtures/mocks. Distinguish BE verified, mock verified and external/deployment not verified. Record absent external review as NOT REQUESTED or PENDING. RF tasks/reports remain historical evidence.
