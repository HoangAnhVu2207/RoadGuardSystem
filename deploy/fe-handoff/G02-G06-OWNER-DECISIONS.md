New envelope exactly `{ "items": [TypedSummary], "nextCursor": null|string }`; empty success is HTTP200 with `items:[]` and `nextCursor:null`. No totalCount/asOf/collection ETag/snapshot guarantee. Keyset order is SQL Server uniqueidentifier ascending; cursor comparisons MUST use the same SQL ordering, never client Guid byte order. Authority is reapplied before page projection; permission changes can reduce the next page. No immutable multi-request snapshot is promised.

PROPOSED error profile for NEW collections only: application/problem+json with `type:"about:blank"`, `title:"Collection request failed"`, integer `status`, request-path `instance`, string `code`, string `correlationId`; no SQL/error stack/resource content. Validate authentication and parent authority before issuing any page/token; do not introduce an existence oracle. Token integrity failures return400 without decoding details. No409/412/428 mutation semantics are added to these GETs. Infrastructure500/503 stay infrastructure failures, not empty successful pages.

Compatibility: additive GET routes only; the 241 historical-operation baseline and current detail DTOs, ETags, operator list, mutations and download checks remain unchanged. Any inability to safely batch these existing guards is an implementation gate, not permission to loosen them.
