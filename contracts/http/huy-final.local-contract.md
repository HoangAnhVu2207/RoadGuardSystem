## H1 wire revision (BE verification in assigned spec)

New login/onboarding credentials use `PersistentRenewable`: server session and refresh expiry are nullable, with no ordinary idle/absolute expiry. Existing stored sessions retain `LegacyBounded`, exact old expiry/revocation and bounded eligibility; migration never promotes them. Session lifecycle and issued role are write-once. Password/reset/logout/disable/role changes still revoke sessions/families. Project membership is checked at project reads/writes/receipt mapping. Last activity is telemetry for new persistent sessions.

Access JWT remains finite (Android 900 seconds; legacy transport uses configured finite lifetime). Refresh response `refreshTokenExpiresAt` and session expiry may be null. `POST /api/v1/auth/refresh` and `/api/v1/auth/android/refresh` accept an optional single visible ASCII `Idempotency-Key` up to150 characters, normalized outer spaces and no internal whitespace. Same original credential/operation retries within two minutes return the same active successor refresh credential after current-authority checks; access JWT may be newly issued. Different-operation reuse, expired retry window or inactive successor retains family-revocation defense. Keyless callers retain strict reuse behavior. Clients must serialize refresh, retain source+operation until acknowledgment and then persist successor atomically. Receipt material is encrypted, never plaintext JSON; retained configured key-ring entries are required to decode receipts during the retry window.

Web login sets a finite 12-hour authentication ticket and a separate protected HttpOnly/Secure/SameSite=Lax renewal cookie. `GET /auth/web/csrf`, then `POST /auth/web/renew` with actor-appropriate `X-CSRF-TOKEN` can renew after ticket expiry without a password. Renewal JSON contains session view only, including nullable `absoluteExpiresAt`/`idleExpiresAt`, `renewable` and ticket lifetime; it never exposes access/refresh credentials. Authorization headers are rejected on renewal, and mismatched valid ticket/renewal identities fail closed. Logout clears both cookies and revokes durable authority. Renewal cookie has a rolling transport storage bound; browser retention/restart behavior and Data Protection key-ring persistence remain external/runbook requirements, not proof of indefinite client storage.

Deadline clock tables are internal producer groundwork, with ten assigned kinds, UTC immutable origin/due, current extension due, actor/reason history, retained breach occurrences, separate danger acknowledgment event/actor and completion. No generic clock API or deadline-triggered execution approval exists. H3–H6 must wire actual domain milestones before those lifecycle capabilities are verified. Official CRS publication remains localized PENDING per the owner clarification; H2 core/sample fixtures proceed independently.

Cursors are bound to publication/hash/layer/filter; URL-encode them. Native and WGS84 layers have separate CRS metadata. Missing data is UNAVAILABLE/INCOMPLETE, not fabricated empty READY. Current authorized historical reads retain pins; no reader silently switches to the latest version. FIELD/Crew package access remains denied until H3 proves exact task/assignment/set pins.

Decision output states `RECORDED_ONLY`; recording VERIFY/CONTINUE/STOP/REASSIGN does not itself change task execution authority. H3 wires the actual task command. Pavement/map/impact commands use one visible-ASCII Idempotency-Key up to150 characters and current authority before new admission or protected replay/conflict/recovery. ## H3 producing contract — independent BE verified

This section records the finite producing contract under the assigned scope. Independent FIELD HTTP/SQL acceptance, fresh/legacy upgrade and affected regression evidence are recorded in the assigned spec. Trusted actual repair-attempt/AFTER integration continues in H4. PM/Supervisor scoped reads and current assigned Crew task reads retain current actor/project/resource checks. Reporter cannot create FIELD work.

The nineteenth route is PM POST `/{taskId}/location-impact-decisions`, with actual impact ID, finite `VERIFY|CONTINUE|STOP|REASSIGN`, reason and optional assignee/structured handover. It binds the actual FIELD_TASK reference and immutable old route/set pins. Applied task action, immutable geometry decision and task event are atomic; output marks `APPLIED`. After first start, cancellation/reassignment requires structured handover: performed-portion state (`NONE|PARTIAL|CAPTURED_INTAKE|UNKNOWN`), summary, actual first-start ID, actual submitted revision IDs and recipient where applicable. Arbitrary reason alone cannot stand for performed-work history. Reassignment preserves first origin and original intakes; it does not silently move task geometry or reset clocks.

Writes require one visible-ASCII `Idempotency-Key` up to150 characters. Task mutations additionally require quoted task-rowversion `If-Match`. Unknown JSON properties and asserted trusted-time/mode/grant fields are rejected. Route/set/layout/slab/map/profile pins remain immutable and historical reads do not switch to latest geometry.

Direct online trusted time is server-controlled; arbitrary offline proof text does not verify original time. Canonical project/origin identity binds operation kind/schema/content/effect across start and submission. Retry/reassignment/supplement never creates a later first origin or resets a deadline.

Submission declares typed measurements with `KNOWN` value, including genuine zero, or `UNKNOWN` null plus reason; dimension/unit and nullable captured location are explicit. LENGTH permits mm/cm/m and AREA uses m². Evidence declares capture origin/checksum/media/purpose even before a file exists.
